# Проработка курса — очередь

Сделано: пункты 1–3 и 20 (карта разделов, порядок, названия, объёмы), пункт 19 в части документации. Раздел 1 написан целиком: 9 уроков. Раздел 2 написан целиком: 10 уроков. Раздел 3 написан целиком: 13 уроков про строки, list, tuple, set, dict, вложенность, распаковку, сортировку и comprehensions. Остальные пункты ждут своей очереди — они начинаются там, где появляются уроки соответствующего раздела.

Источник: содержательный разбор плана (каркас хороший, охват широкий, до middle не хватает глубины и проектной практики). Новые большие разделы не добавлять — перераспределить уроки внутри существующих.

Оценки плана: ширина 9/10, глубина 6/10, последовательность 7/10. Потенциал junior+ высокий, до middle — после углубления. Ориентир ~220 коротких уроков, не «закрыть обещание 200+».

Траектория: нулевой Python → уверенный Python → алгоритмы → файлы и библиотеки → тесты → Git → API → SQL → аналитика → async/backend → инженерия → реальный проект. Треки Developer/Analyst не разделять.

## Что менять

1. **Основы.** Не переходить к условиям после третьего урока. Раздел из 8–9 уроков: первый код, переменные, ввод и типы, арифметика, сравнения и bool, логические операторы, истинность и `None`, f-строки, итоговая задача. `bool`/`None` можно упомянуть рано, понимание — вместе со сравнениями.
2. **Названия.** Оставить «Старт и основы», «Условия и циклы», «Строки и коллекции» (внутри: строки → list → tuple → set → dict → вложенные → распаковка → comprehensions). «Функции» → «Функции и области видимости». «Файлы, данные и модули» → «Файлы, сериализация и модули» (`pathlib`, текст, кодировки, CSV, JSON, даты, stdlib, import/package). «ООП» → «Объектно-ориентированное программирование» плюс композиция. «Python глубже» → «Продвинутый Python».
3. **Порядок.** Алгоритмы раньше ООП: функции → алгоритмы → файлы → ошибки → ООП. ООП алгоритмам почти не нужно.
4. **Типизация.** Не откладывать до инженерии. После функций вводить аннотации постепенно (`float`/`int`, `list[str]`, `dict[str, int]`, `Optional`, `Union`, `|`, `TypeAlias`, `Protocol`, generics). Отдельный инженерный блок: mypy/pyright и конфигурация. Аннотации Python сам не проверяет.
5. **Алгоритмы, 14–16 уроков.** Big O, массивы/списки, хеш-таблицы, стек, очередь и `deque`, линейный и бинарный поиск, сортировки, рекурсия, деревья, BFS, DFS, графы, кратчайшие пути, жадные алгоритмы, введение в ДП. Цель: оценить сложность и выбрать структуру данных.
6. **Продвинутый Python.** Добавить контекстные менеджеры, `__iter__`/`__next__`, функции как объекты, замыкания, декораторы, `functools`, `collections`, дескрипторы (обзорно). `match` — один короткий урок, не в одном ряду с генераторами и декораторами.
7. **Файлы и stdlib.** `with`, UTF-8, бинарные файлы (концепт), `re`, `collections`, `itertools`, `functools`, `datetime`, `math`, `statistics`, `secrets` vs `random`, структура своего пакета.
8. **CLI и Git без дубля.** Убрать статус bonus у командной строки. Один раздел «Командная строка, окружение и пакеты»: терминал, пути, запуск Python, `python -m`, версии, `venv`, `pip`, `pyproject.toml`, зависимости, переменные окружения, структура проекта. Следующий раздел только «Git и GitHub»: init, status, add, commit, branch, merge, rebase, remote, pull, push, PR, конфликт, review, Actions. Не держать «начало Git» в окружении и отдельный Git следом.
9. **Исключения и тесты, 10–12 уроков.** К traceback, try/except, raise, assert, pytest добавить `finally`, свои исключения, цепочки, `logging`, `breakpoint()`, fixtures, parametrization, mocking, unit/integration, coverage.
10. **HTTP/API, 10–12 уроков.** URL, query/path, headers, body, JSON, requests или httpx, timeout, retry, ошибки, pagination, rate limit, авторизация, API keys, Bearer, cookies, OpenAPI, идемпотентность, webhooks.
11. **SQL, 14–16 уроков.** WHERE, ORDER BY, GROUP BY, HAVING, CASE, NULL, агрегаты, подзапросы, JOIN, UNION, CTE, окна, даты, индексы, ключи, ограничения, нормализация, транзакции, изоляция, EXPLAIN, SQLite и PostgreSQL концептуально. Затем SQLAlchemy: Engine, Session, модели, SELECT, INSERT/UPDATE/DELETE, relationships, transactions. Обязательно Alembic.
12. **Pandas, 16–18 уроков.** NumPy: массивы, shape, dtype, индексация, slicing, broadcasting, vectorization, агрегаты, маски. Pandas: Series, DataFrame, создание/загрузка, индексация, loc/iloc, фильтр, столбцы, пропуски, groupby, agg, merge, join, concat, pivot/reshape, даты, строки, категории, сортировка, дубликаты, выбросы, CSV/Excel/JSON, экспорт, `apply` и когда его не использовать.
13. **Разделить визуализацию и статистику.** Визуализация 8–10: matplotlib, seaborn, типы графиков, подписи, несколько графиков, распределения, boxplot, scatter, ряды. Статистика 12–14: описательная, выборки, распределения, среднее/медиана, дисперсия, интервалы, корреляция, тесты, p-value, ошибки I/II рода, размер эффекта, A/B, простая регрессия.
14. **Jupyter.** Блок «Jupyter и исследовательский анализ» перед NumPy/Pandas: notebook, Markdown, ячейки, повторяемость, импорт, EDA, графики, сохранение, отличие от production-кода.
15. **Производительность.** Название: «Производительность, конкурентность и асинхронность» или «Производительность и конкурентное выполнение». `asyncio` — не то же самое, что multiprocessing. Уроки: измерение, Big-O на практике, память, profiling, I/O-bound vs CPU-bound, threading, GIL, multiprocessing, futures, async/await, asyncio, сетевые задачи.
16. **Backend.** Не учить Flask и FastAPI одинаково глубоко. FastAPI — основной framework (приложение, маршруты, request/response, Pydantic, validation, DI, async, БД, auth, authorization, ошибки, middleware, OpenAPI, тесты). Flask — один урок «чем отличается».
17. **Инженерия — главная дыра до middle.** Структура проекта, слои, конфигурация, типизация, линтер/форматтер, pre-commit, pytest, coverage, логи, секреты, Docker, Compose, CI, миграции, health checks, production configuration, уязвимости зависимостей, code review, базовые метрики. Плюс 2–4 урока безопасной разработки: SQL injection, path traversal, SSRF, unsafe deserialization, секреты, пользовательский ввод, зависимости.
18. **Контрольные проекты.** После функций/коллекций — консольное приложение (логи, задачи или CSV). После SQL и Pandas — исследование: загрузка, очистка, SQL, Pandas, статистика, графики, выводы. После HTTP — FastAPI + БД + Pydantic + тесты. Финал — всё вместе.
19. **Типы заданий.** `choice` / `predict_output` / stdout-`code` оставить на первые 30–50 уроков. Дальше: структура проекта, функция и тесты, баг, endpoint, несколько файлов, SQL, CSV/DataFrame, упавший тест, сложность алгоритма, PR. От «выведи 42» к работе с существующей кодовой базой. Обновить `TASK_AUTHORING.md`.
20. **ИИ-блок.** «Бонус. Vibe coding» → «Бонус. Разработка с ИИ-помощником». Цикл: постановка → контекст → генерация → проверка → тесты → отладка → рефакторинг → безопасность → review. Не «попросить AI написать код».

## Не добавлять

Django. Flask + Django + FastAPI вместе. Deep Learning. Обязательный scikit-learn (только короткий опциональный блок). DevOps целиком. Kubernetes. Сложную распределённую архитектуру. Метапрограммирование во всех подробностях.
