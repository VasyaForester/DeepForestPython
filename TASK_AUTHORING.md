# Как писать задания

Типы этой версии: choice, predict_output, code. У code есть starter_code, tests со stdin и expected_stdout, три подсказки, solution и explanation. Сложность 1–4 становится весом в GPA. Контекст задания: neutral, development, analytics, security или business.

Эти три типа рассчитаны на первые разделы. Дальше курс переходит к заданиям на существующем коде: починить баг, написать функцию вместе с тестами, изменить несколько файлов, написать SQL-запрос, исследовать таблицу, улучшить сложность алгоритма. Новый тип задания добавляется вместе с проверкой в `scripts/validate_content.py`, иначе материал не пройдёт валидацию.

Решение и примеры прогоняются системным Python, а ученик исполняет код в Pyodide. Валидатор запрещает `eval`, `exec`, `breakpoint` и импорт модулей вне общего списка (`json`, `math`, `re`, `datetime`, `collections`, `functools`, `itertools`, `sqlite3` и соседние модули стандартной библиотеки, которые не тянут `os`). Свои функции вызывать можно. `pandas`, `numpy`, `matplotlib`, `pytest` и `fastapi` в браузерный runtime не входят: в теории их называют прямо, а проверяемое решение делает ту же работу на чистом Python или `sqlite3`.
